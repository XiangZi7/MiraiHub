# AI Agent

OpenAI Chat Completions 兼容格式（包括 DeepSeek）和 OpenAI Responses 的对话请求使用流式响应，回复会逐步显示，并区分思考、生成回复和准备工具调用。连接最多等待 10 秒；连续 300 秒未收到任何数据或单次请求达到 30 分钟时超时。思考分片与心跳也计为连接活动。停止或切换会话会取消正在等待的模型请求。中转站若忽略流式参数并返回 JSON，仍可读取完整回复，但不能逐步显示。Claude 原生 Messages 暂沿用非流式请求。

工具参数在流式响应完整结束并校验后才进入原有执行与审批流程；中途断开、输出长度超限或参数不完整时不执行本次工具调用。已显示的部分回复保留在聊天记录中，但不作为完整回复加入模型上下文。流式响应仍保留 DeepSeek 的 reasoning_content 供后续工具对话使用，界面仅显示思考状态。非流式模型响应最多 1 MB；流式传输最多 16 MB，其中累计增量数据最多 1 MB。

Chat Completions 工具分片中的 `id`、`type` 可能只在首片返回，后续分片的空字符串或 null 占位不会覆盖已有信息。不同的非空 ID 仍视为冲突；函数名和参数按原始增量拼接，不猜测或修补命令。工具调用校验失败时，会分别提示 ID 缺失或冲突、字段类型错误、函数名缺失、参数缺失或 JSON 不完整；错误不回显原始参数，本次工具不会执行。

在设置 → AI Agent 中添加配置，填写名称、API 格式、基础地址、模型 ID 与 API Key，然后保存并使用，或保存并测试连接。支持 OpenAI Chat Completions（function tools）、OpenAI Responses（function_call / function_call_output）和 Claude 原生 Messages（tool_use / tool_result），不包含 Gemini 原生 generateContent 协议。模型必须支持工具调用；不会自动选择收费模型，只有发送消息、获取模型或测试连接时才请求服务。

如果同一中转站在其他客户端使用 `/responses`，请选择「OpenAI · Responses」，基础地址通常填 `https://服务地址/v1`；也可填完整 `/v1/responses`，程序会规范化接口路径。Responses 使用 `store: false`，后续请求携带本地会话上下文与返回的加密推理项。只有收到 `response.completed` 且完整输出校验通过后，工具调用才进入审批；仅收到参数结束事件或连接关闭不会执行工具。

遇到「服务未返回兼容的流式响应」且后台显示 `client_gone / context canceled`，先核对 API 格式及原始 SSE 分片。解析失败会使客户端关闭请求，后台的取消记录本身不能区分协议不匹配、主动停止或网络断开。Chat Completions 允许中转站用空字符串表示尚未结束的 `finish_reason`，兼容已知心跳、独立用量分片及不含新内容的重复结束分片；未知数据、结束后的新正文或冲突结束状态仍会报错。协议不匹配时会提示选择 Responses 或 Claude Messages，不自动重试或切换协议。

每份配置独立保存，同一服务可以添加多份官网和中转站配置。提供 OpenAI、Claude、DeepSeek、豆包（火山方舟）、Gemini 和自定义地址模板；Claude 默认使用 Messages，Gemini 使用官方 OpenAI 兼容入口，其他模板默认使用 OpenAI 格式。名称、地址和 API 格式都可修改。豆包模型 ID 或接入点 ID 请按自己的方舟服务填写；没有模型列表接口的中转站可以手动输入模型。

SSH 与数据库的 AI 面板均有配置下拉框。切换配置会停止当前运行，并在当前会话继续对话；新消息使用选中的配置。历史记录仅在继续发送消息时随上下文发给当前配置的模型服务，查看记录本身不会请求模型。设置窗口中的未保存草稿可来回切换编辑，关闭窗口后丢弃。旧版单配置会自动迁移为“原有配置”，保留地址、模型、启用状态和加密密钥。删除正在使用的配置后，需要明确选择另一份配置才会继续使用 AI。

SSH 工作区和数据库工作区都有 AI Agent 标签；分屏按钮在编辑器旁显示 AI。原有第二个 SSH 终端仍可从“新建或关闭第二个 SSH 终端”按钮打开。右上角的新对话图标新建聊天，旁边的历史图标打开聊天记录气泡，支持搜索和切换，按最近更新时间排序。每条会话右侧可以重命名或删除，删除需要确认；修改其他历史记录不会切换或中断当前会话。名称默认取第一条消息，可改为 1 至 60 个字符，继续聊天和重启后保留新名称。新建或关闭面板会保留记录。重新连接或重启后自动显示当前目标最近的一段会话，可继续追问和复制记录。

会话按连接类型、服务端地址、端口、账号分开；数据库还按数据库引擎与库名区分。同一目标重连后的临时会话 ID 不影响历史记录。恢复历史仅加载文字、Markdown 与操作记录，不恢复审批和正在执行的任务。继续发送时重新绑定当前连接、生成新的运行 ID 和审批；未完成的旧操作结果标为未确认，不会自动重放。

## 输入区与附件

模型选择位于输入框底栏，顶部不再显示模型配置行或服务地址。右上角的新对话图标统一开始新会话，失败或停止后也使用此入口。底栏左侧的“+”选择本地文件，支持 UTF-8 文本、日志、代码、CSV 与 SQL；暂不解析图片、PDF、Office 或其他二进制文件。每条消息最多 4 个附件，单个最多 64 KB、合计最多 128 KB，不自动截断文件。可移除附件，也可只发送附件。附件实际内容计入所选配置的上下文容量；已有历史较长时仍可能需要调高任务容量。

选文件只在本机读取，发送消息时才将文件名和内容交给所选模型。附件元数据展示在消息气泡中，完整内容随上下文加密保存，恢复会话后可继续参考。发送前失败会恢复草稿；切换连接、模型或会话时清空待发送附件，迟到的文件读取不会进入新会话。

输入区的审批菜单提供三种模式：

| 模式 | 实际执行行为 |
| --- | --- |
| 请求批准 | 所有工具逐次确认，包括固定只读探针和结构读取。 |
| 帮我批准（默认） | 内置只读工具与明确识别的常见诊断命令、简单 SQL 元数据检查自动执行；修改类与未识别操作逐次确认。 |
| 完全访问权限 | 当前连接的已提供工具自动执行，包括可修改或删除数据的 Shell / SQL 和外部 MCP 工具；自动执行的命令会留下操作记录。 |

模式随每轮发送交给后端，运行中或等待审批时不能修改，需先停止当前轮次。新对话、切换模型、连接或历史会话时回到默认模式；历史记录不保存或恢复完全访问权限。完全访问权限只影响当前连接已有的工具，不增加本机文件访问工具，连接绑定、参数校验、容量限制和停止机制仍然生效。

自动检查包括 `command -v pm2 && pm2 --version`、`ls -lah`、`df -h`、`ps aux`、`ss -tulnp`、`systemctl status nginx --no-pager`、`journalctl -u nginx -n 100 --no-pager` 和有限行数的日志查看。后端按完整命令和明确允许的参数判断；组合命令中的每一段都必须符合规则。安装、重启、写入、删除、重定向、命令替换、敏感路径和未知语法仍需审批。SQL 仅放行 `SELECT 1`、`SHOW TABLES`、`DESCRIBE` 等明确识别的简单检查，不按 `SELECT` 前缀放行任意查询。这是操作审批策略，不是对被篡改的远端命令或文件系统的隔离。

审批过期后自动撤销本次待执行操作并恢复输入，可在原会话发送新指令；过期前后均可停止或拒绝。过期不会自动批准、续期或重试命令。聊天正文、工具输出和审批说明支持选中后复制，消息与审批的目标、命令、说明也提供复制按钮。

## 任务容量

设置 → AI Agent → 任务容量提供以下预设，每份模型配置独立保存，SSH 与数据库共用。已有配置保持标准容量，也可以选择“自定义”分别调整三项。

| 预设       | 每轮模型请求 | 本地上下文容量 | 历史消息（含系统消息与工具结果） |
| ---------- | ------------ | -------------- | -------------------------------- |
| 标准       | 8 次         | 180 KB         | 64 条                            |
| 增强       | 32 次        | 1000 KB        | 256 条                           |
| 深度       | 64 次        | 4000 KB        | 1024 条                          |
| 自定义范围 | 1–128 次     | 64–4000 KB     | 16–2048 条                       |

上下文按消息序列化后的 UTF-8 字节数计算，1 KB = 1000 字节，不等于模型的 Token 窗口。模型服务自身的上下文限制仍然适用。每次发送用户消息开始新一轮请求计数；历史消息与上下文容量跨轮累计。调大容量可能增加请求耗时与用量。达到上限时，提示会明确指出具体限制；保存更大的容量后，可从聊天记录选择原会话继续，使用新的限制。

## 执行边界

- 默认自动只读：固定 Linux 系统/磁盘/进程名称/网络统计探针；数据库对象与字段结构（MySQL、PostgreSQL）。“请求批准”模式也会确认这些工具。探针不接收任意 Shell 参数，元数据查询复用参数绑定。
- 默认“帮我批准”和“请求批准”模式下，所有自定义 Shell 和 SQL 都需审批，包括 SELECT/EXPLAIN：函数、CTE、脚本拼接可能产生副作用，不能仅靠字符串前缀判断只读。“完全访问权限”按用户选择自动执行。
- 后端校验工具名称、连接类型、严格参数结构、长度与控制字符；未知工具、额外字段、重复字段均不执行。模型一次返回多个工具调用时，一个都不执行，而是逐个回复「请一次只调用一个工具」，对话继续而不是整轮失败。
- 审批包含后端记录的真实目标、完整原文、AI 提议原因，锁定在具体会话与数据库版本。审批 5 分钟到期，随机 ID，在锁内消费后才执行；不能重复使用或从模型工具中批准。
- 数据库使用独立连接池执行 AI 操作，避免手动编辑器中的 USE/SET 改变已批准 SQL 的初始目标。切库再切回也会使旧审批失效。批准的 SQL 本身若包含跨库引用或 USE，将按显示的完整 SQL 执行。
- 切换标签/连接、关闭 AI 面板、停止、清空或保存 AI 设置会撤销后续执行。停止不是回滚；已经开始执行的操作可能已提交或仍在远端运行。
- 每轮模型请求和上下文按所选任务容量限制。工具输出传入模型最多约 16 KB，模型响应最多 1 MB，保留最多 32 个后端对话。Shell 通道读取最长 30 秒；SQL 单语句 20 秒、整个脚本 45 秒，最多保留每条语句前 20 行。驱动仍可能接收大型单行数据，读取业务数据时应自行限制范围。

## 凭据与数据

API 配置整体使用 Windows DPAPI 按当前操作系统用户加密，保存在应用数据目录的 ai-settings.bin；密钥不会回传给页面，不进入普通设置、连接导出或日志。其他平台未接入系统密钥存储时拒绝保存，不回退明文。运行时密钥仍需留在本机进程内存，DPAPI 不能防御同一用户权限下的恶意程序。

远程 API 强制 HTTPS，HTTP 只允许 localhost/127.0.0.1/::1。地址不得包含账号、密码、查询参数或片段；HTTP 重定向被禁用。服务错误会带上服务商自己的说明（如额度不足、模型不存在），但会脱敏密钥形状的字符串、截断到 500 字符，并且不回显请求地址、请求头和无法识别的响应体。更换服务地址必须重新输入密钥或明确清除旧密钥，避免误把旧密钥发往新服务。

## 外部 MCP 服务器

设置 → AI Agent 的「固定安全规则」下方可以添加外部 MCP 服务器，让模型调用本应用内置工具之外的工具。

- 支持两种传输：本地程序（stdio，换行分隔的 JSON-RPC）和远程服务（Streamable HTTP）。stdio 在 Windows 上不弹出控制台窗口，启动或调用失败时会把程序的标准错误输出附在错误信息里。
- 配置与 AI 配置存在同一个加密文件里。环境变量和请求头的值只在保存时写入，页面只显示「是否已设置」，不会读回明文。
- 发现到的工具以 `mcp__服务器名__工具名` 暴露给模型，并按当前连接类型过滤（可限定 SSH、数据库或 Redis）。
- 外部服务器可以自己声明工具是只读的，这个声明不可信。所以「请求批准」和「帮我批准」模式下，每次调用外部工具都要单独确认；只有「完全访问权限」会自动执行。审批卡片显示服务器、工具名和参数。
- 外部 MCP 服务器以当前用户的权限在本机运行，不在 SSH 与数据库的审批边界之内。不要添加你不信任的服务器。

聊天与操作记录在每次消息、工具步骤、审批结果及停止后自动保存到应用数据目录的 ai-conversations/*.bin，使用 Windows DPAPI 加密并通过临时加密文件替换写入；保存失败会在面板提示。记录包含对话上下文与附件内容，不包含模型 API Key、连接凭据、实时连接句柄或可执行审批。模型仅收到用户消息、主动添加的附件和所调用工具的结果，不自动读取 SSH 密码、私钥、环境变量或终端缓冲区。输入、附件与操作输出可能包含敏感数据，会发送给配置的模型服务；添加附件时会在输入区提示其发送与保存方式。删除本机聊天记录不等于删除服务商已经接收到的数据。

AI 回复支持 Markdown 标题、列表、加粗、行内代码、代码块、引用和表格；代码块可复制，宽代码与表格可横向滚动。用户消息保持原文并显示为右侧气泡，AI 回复带头像。原始 HTML 会转义，链接仅允许 HTTP/HTTPS，图片显示为需点击的链接，不自动加载。代码块只能复制，不会触发执行。工具结果、数据库名称、日志都是不可信数据。提示词用于引导模型；真正的执行权限由 Rust 工具分派与审批状态机控制。

这些限制针对 AI 发起的操作，不改变用户手动操作终端/数据库的权限，也不是针对已被攻陷的桌面进程或远端服务器的隔离沙箱。
