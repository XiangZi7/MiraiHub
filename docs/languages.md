# 界面语言

「设置 → 通用 → 界面语言」提供跟随系统、简体中文和 English，默认跟随系统。保存后同步到所有已打开的 WebView；取消不会改变语言偏好。

Rust 的 `get_system_locale` IPC 返回系统界面语言。Windows 使用 `GetUserDefaultUILanguage`，避免把区域日期格式当作显示语言。Vue 在挂载前读取结果并初始化 vue-i18n，中文区域变体统一使用 `zh-CN`，其他语言回退到 `en-US`。显式选择中文或英文时优先使用用户选择；跟随系统时，窗口重新获得焦点会重新读取系统语言。浏览器预览使用 `navigator.language`。

翻译资源位于 `src/i18n/modules/`：`en-US.ts` 和 `zh-CN.ts` 汇总原有资源、`features.ts` 功能文案、`parameterized.ts` 双语完整句子和 `native.ts` 原生 AI 状态及错误。中文源文案键沿用现有约定，带变量的提示使用插值，不在界面里拼接词序。

文件浏览与传输、AI 聊天及审批、连接表单、SSH 密钥、数据库对象和数据编辑、导入导出、远端编辑器、隧道、批量操作和终端控制均使用 vue-i18n。设置、状态、下拉选项和时间格式在渲染或 computed 中读取语言，已打开的界面随语言切换更新。组件默认提示在渲染时翻译，不能在 `withDefaults` 中调用组件作用域的 `t`。

原生托盘菜单使用系统语言。连接名称、用户输入、AI 回复、SQL 和服务器输出保持原样；已保存的聊天内容不会重写。`translateNativeMessage` 只翻译已知的应用提示，保留外部诊断详情。已有通知按产生时的语言保存，已知的原生提示可在展示时翻译。

`tests/i18n.test.mjs` 验证语言解析、回退、设置翻译和原生语言初始化。`tests/i18n-ui.test.mjs` 挂载实际传输和 AI 组件，验证中英文即时切换、用户内容保留、完整资源编译和插值参数一致性。`tests/skin.test.mjs` 验证旧设置兼容与语言偏好的持久化。
